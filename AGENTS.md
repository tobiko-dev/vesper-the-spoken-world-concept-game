# Project documentation

- Keep `README.md` focused on the game: screenshots first, a short premise, playable features, and an accurate play link.
- Put setup commands, dependencies, architecture, hosting, tests, performance details, and implementation limitations in `TECHNICAL.md`.
- Use real captures of the game. Label earlier development screenshots and concept art accurately; do not present them as current gameplay.
- Keep the existing private preview labeled private until a public deployment has been verified.
- Preserve the current Sites configuration when changing the separate static web build.
- Do not add a license, publish the private preview publicly, or claim future worldbuilding features are implemented without an explicit decision.
